# 架构

```text
React 视图 / Zustand 状态
  ├─ useAnalysis → 每游戏独立 Web Worker → Engine/bridge.ts → Engine/domain
  └─ StatsPlatform → Tauri IPC → Rust 原生目录和本地持久化
```

`Engine/` 保留原项目的解析、Schema、对象注册表、查询、统计、竞技场、流派及官方中文库。新界面直接导入上游 TypeScript；不使用、修改或分发原生项目打包后的 `engine.js`。官方本地化资源来自原项目的上游文件，不在页面内复制译名。

`src/services/platform.ts` 是文件、目录、导入导出和偏好持久化的唯一平台接口。安装应用通过受限 Rust commands 操作；浏览器 adapter 仅用于隔离预览。界面不获得任意原生文件写入权限。目录授权由原生选择器或 OS 拖放事件创建并持久化；拖放接口只消费原生事件保存的路径，不接受前端传入任意路径。重新扫描要求与已授权规范路径相同。无 HTTP、shell 或广泛 filesystem capability，CSP 禁止远程连接和脚本。

Rust 的文件选择、目录扫描和读写在 `spawn_blocking` 中执行。扫描跳过隐藏目录和符号链接，按 profile.save 选择当前 Profile，拒绝多个账号／来源、多个 progress.save 及读取过程中变动的文件；错误会明确返回，不静默截断。权威数据不再使用 32 MiB 单文件、50,000 文件或 512 MiB 数据集的固定上限。授权保留用户所选根目录，实际 Profile 来源每次解析并独立归档。后台每 2 秒比较元数据指纹，连续稳定快照后同步，每 60 秒复核内容；启动及回到前台立即检查。失败保留当前数据并自动重试，各游戏的暂停开关独立。所有 `.run` 和 `progress.save` 均只读；原始存档导出使用 `.run.json`，且不能写入授权来源目录。

解析、Schema 验证、导入去重、完整结果排序／分页、统计及大型 JSON 比较和导出序列化均在 Web Worker 中执行。每个游戏一个 Worker，避免引擎全局游戏状态交叉污染。界面只保留轻量对局摘要和累计计数；启动摘要或分析磁盘缓存命中时不读取完整存档。缓存未命中、复盘、导入或导出才在 Worker 延迟载入完整数据。Worker 的文件请求通过消息交给 AnalysisClient，再由 StatsPlatform 调用 Rust，不直接使用文件或网络 API。数据加载与提交共享每游戏串行队列，原生选择器开始时捕获游戏，后续切换不会改变导入目标。请求串行执行；同一组件的排队旧请求可被最新选择替换。已运行的同步统计不能中断，其结果按游戏、修订与请求身份保护，不能覆盖新选择。Worker 故障后恢复轻量检查点，再按需读取权威数据。

每游戏内存分析缓存最多 36 条、32 MiB，单条最多 4 MiB；每个视图最多六个响应、8 MiB。`derived-v2` 的磁盘分析结果最多 128 项、128 MiB，另有最多 16 MiB 的启动摘要及 4 MiB 的卡池缓存。缓存身份包含游戏、数据文件元数据与原子替换身份、引擎／本地化／Worker 内容摘要和缓存格式版本；请求键包含完整筛选和页面参数。切换游戏不会清空未变数据的 Worker 缓存。缓存校验失败、缺失、超限或不可写时回退到正常计算。列表局部状态和滚动位置也受数量上限限制。权威存档和来源归档不属于派生缓存。

导入在 Worker 中先准备完整候选数据，所有文件成功后才调用原生存储。`dataset.json` 使用同目录临时文件、flush 和原子替换；Windows 同样使用 tempfile 的覆盖式 persist。存储失败回滚引擎与归档检查点，并清理未提交副本。按来源哈希分开存储归档，保存接受的原始内容副本和归一化版本；历史运行保留，冗余进度快照最多八份。切换回旧来源时恢复其已导入历史，即使原目录已经没有历史文件。原游戏目录中消失的文件不会删除已有归档。游戏来源不得与应用存储目录重叠，应用数据子目录也不能通过符号链接重定向。

原生旧数据保持 `runs / progress / source / importedAt / manifest / fileRunIDs` 结构；`importedAt` 仍是自 2001-01-01 起的秒数。额外 `importMetadata` 记录新导入的时间戳、内容摘要和接受的版本摘要，旧原生 Codable 会忽略此字段。旧 manifest 在新来源首次同步时重新生成 SHA-256 内容摘要。

完整迁移通过原生选择器读取旧应用目录与可选 plist 偏好文件，支持两个游戏的 dataset、全部 `save-archive-v1` 来源、原始与归一化副本、接受的历史版本、收藏 ID、四组筛选、主题、最低样本量、旧保存视图及同步偏好。Worker 合并时保留现有记录，并映射同名不同对局的新 ID。所有所选来源先校验并暂存，再统一原子替换各归档检查点、所选当前数据集和偏好；失败回滚，启动时恢复未完成的迁移日志。重试只提交本次所选来源；迁移期间暂停收藏、筛选及设置写入，避免覆盖统一提交的偏好。旧目录不写回，旧书签不授予新应用读取权限。来源名称缺失时保留稳定历史来源，并保存原来源哈希映射以支持重新选择原目录。存档管理可独立打开来源归档，无需游戏目录仍然存在。

布局通过同一设计系统响应窗口宽度。宽屏侧栏常驻，窄屏切换抽屉；列表使用浏览器表格并分页，矩阵分块显示，固定不透明表头及左名称列。列表保留搜索、排序、收藏与分页；详情继承入口筛选，逐层返回恢复原上下文。沿用 Tauri 的每页独立筛选范围，并提供多选、日期快捷和逐项移除。颜色集中在 `src/styles/theme.ts` 和 CSS tokens，角色身份按稳定 ID 绑定；数值大小、比例和偏好采用各自色阶，完整筛选列排名与实际数值颜色强度分别计算。

本次仅支持 Windows 和 macOS。Android SAF 需要另行实现 platform adapter、Rust/Kotlin 授权目录插件和移动宿主工作流；本工程不会将浏览器目录 API 冒充 Android 原生存档访问。

原生进程持有应用数据目录的跨平台文件锁，防止第二实例写入同一数据或清理正在进行的迁移。标准库文件锁要求 Rust 1.89+，本地使用 Rust stable；应用支持的操作系统版本不变。
